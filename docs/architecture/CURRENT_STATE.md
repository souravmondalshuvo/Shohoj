# Current State — Verified Inventory (Phase 0)

> This is the canonical "what actually ships today" reference. Where this
> contradicts older migration docs, this document wins (see Stale Documents).

## 1. Shipping product

Shohoj ships as **three self-contained HTML files** generated by `build3.py`:

| Output | Template | JS list in build3.py | Notes |
|---|---|---|---|
| `shohoj.html` (~3.1 MB) | `index.html` | `MAIN_JS_FILES` (54 files) | main app, seeds injected |
| `admin.html` (~0.47 MB) | `admin/index.html` | `ADMIN_JS_FILES` (11 files) | admin dashboard, no seeds |
| `profile.html` (~0.36 MB) | `profile/index.html` | `PROFILE_JS_FILES` (6 files) | account hub |

These `*.html` outputs are **gitignored build artifacts** — never committed (confirmed
via `git ls-files`). Deployment is **GitHub Pages** (`.github/workflows/cd.yml`).

`build3.py` is a string concatenator: per file it strips `import`/`export` with regex
(`strip_imports_exports`) and joins the bodies into **one `<script>` scope**, inlines
CSS, keeps `js/auth/firebase.js` + helpers as a separate `type="module"` block (CDN
Firebase imports), injects seed data into placeholders, then hardens CSP by replacing
`'unsafe-inline'` in `script-src` with SHA-256 hashes of each inline script.

## 2. Frontend (legacy, shipping) — `js/`

62 ES modules, loaded un-bundled in dev/e2e (raw ESM + import map in `index.html`) and
flattened by `build3.py` in production. Structure:

- `js/core/` — domain-ish logic mixed with state: `grades`, `gpa-core`, `calculator`,
  `catalog`, `faculty`, `reviews`, `papers`, `studyGroups`, `planner-core`, routine\*
  (`routineState/Grid/Faculty/Suggestions/Export/PlannerImport`), `connectFeed(Client)`,
  `freeRooms`, `seatStatus`, `seatWatch`, `calendarExport`, `state`, `dispatch`,
  `departments`, `helpers`.
- `js/ui/` — DOM rendering via HTML-string templates + `innerHTML`: `render`, `simulator`,
  `playground`, `modals`, tabs (`reviewsTab`, `papersTab`, `groupsTab`, `routineTab`,
  `freeRoomsTab`, `seatsTab`, `profileTab`, `adminDashboard`), `difficultyMap`, `charts`,
  `tracker`, `suggestions`, `feedback`, `previewModal(Pdfjs)`, `feedLive`.
- `js/auth/` — Firebase: `firebase-init`, `auth-service`, `admin-service`, `paper-service`,
  `review-service`, `user-sync-service`, `firebase` (kept as `type="module"`).
- `js/config/runtime-config.js` — window-var config (generated from env / template).
- `js/animations/`, `js/import/` (transcript `parser` + `transcript-core`), `js/main.js`.

### Shared mutable state & global bridge
Single mutable `state` object (`js/core/state.js`) + `js/core/dispatch.js` action registry.
**~80 `window._shohoj_*` bridge functions** connect the bundled non-module scope to the
Firebase `type="module"` block and across tabs (e.g. `_shohoj_onSave`, `_shohoj_applyState`,
`_shohoj_currentUid`, `_shohoj_fetchReviewsByCourse`, `_shohoj_createStudyGroup`,
admin `_shohoj_approvePaper`/`_shohoj_deletePaper*`, etc.). Plus `_dm_*` for Difficulty Map.

### localStorage keys (only two)
`shohoj_theme`, `shohoj_pdfjs_preview`. Academic calculator state persists via the
typed store under `src/services/storage/` **only in the React island path** — the legacy
calculator keeps state in memory + cloud (Firestore), not localStorage.

## 3. Migration code (`src/`, TypeScript/React) — NOT the default UI

- `src/core/*.ts` — typed ports of domain logic (`gpa`, `grades`, `catalog`, `faculty`,
  `reviews`, `papers`, `planner`, `transcript`, routine\*, `seatStatus`, `seatWatch`,
  `freeRooms`, `calendarExport`, `connectFeed*`) + `errors.ts`, `result.ts`, `types.ts`.
  Parity with legacy is asserted by `tests/typedCoreParity.test.js`.
- `src/features/calculator/*.tsx` — React calculator (semesters, course rows, summary,
  autocomplete) behind an **opt-in flag**, Vite-built, **not present in `shohoj.html`**.
  Still calls some legacy globals via `calculatorBridge.ts`.
- `src/services/storage/` — `keyValueStore`, `migrate` (versioned), `backup`,
  `syncDecision`. **Migration utilities exist but are not wired into the live legacy
  persistence path.**
- `src/state/` — `ThemeProvider`, `NotificationProvider` (+ pure `theme.ts`,
  `notifications.ts`). `src/app/` — `AppProviders`, `ErrorBoundary`.
- `src/react/` + `src/firebase/firebase-entry.js` — island entry points.

Vite config (`vite.config.js`) builds a multi-entry `dist/` (not yet the production host).

## 4. Backend — one Cloudflare Worker (`worker/`)

`worker/index.js` routes by `url.pathname`: `/upload`, `/download`, `/file` (delete),
`/reviews`. Backs **R2** for paper files; verifies Firebase tokens; scheduled handler
delivers **seat-alert emails** via Resend (cron, tested in unit suite). Deployed via
`.github/workflows/deploy-worker.yml`.

## 5. Data layer — Firebase

- **Auth**: Google sign-in, App Check (ReCaptcha v3), admin via custom claim `admin:true`.
- **Firestore collections** (from code + `firestore.rules`): `facultyReviews`,
  `reviewReports`, `papers`, `paperReports`, `studyGroups`, `studyGroupMembers`,
  `studyGroupReports`, `appFeedback`, `appFeedbackUpvotes`, `facultyProfiles`, `adminLogs`.
- `firestore.rules` (16 KB) enforces deterministic review IDs, review immutability,
  paper owner paths, admin-claim gates. `firestore.indexes.json` defines composite indexes.
- Live external feed: `usis-cdn.eniamza.com/connect.json` (seats/rooms/schedule).

## 8. Confirmed architectural defects (Phase 1 target)

`build3.py`'s flat scope contains **8 unsafe top-level identifier collisions** in
`MAIN_JS_FILES` where the last-loaded module silently wins (detected by
`scripts/check_bundle_collisions.py`):

| Identifier | Files | Winner | Live impact |
|---|---|---|---|
| `_render` | difficultyMap.js, groupsTab.js | groupsTab `_render()` | Difficulty Map calls `_render(root,entries)` → gets the no-arg groups renderer |
| `_t` | feedback.js, groupsTab.js | feedback theme obj | Groups reads `_t().cardBg`/`.danger` → `undefined` |
| `_timeAgo` | feedback.js, groupsTab.js | feedback `(ts)` | Groups passes a group object to a timestamp fn |
| `_signInPrompt` | reviewsTab.js, groupsTab.js | groupsTab markup | Reviews sign-in prompt renders groups markup |
| `_starBar` | reviews.js, reviewsTab.js | reviewsTab classes | reviews.js stars use the wrong style hooks |
| `_isAuthReady` | groupsTab/papersTab/reviewsTab | identical | benign today, fragile |
| `_isSignedIn` | groupsTab/papersTab/reviewsTab | identical | benign today, fragile |
| `_toast` | groupsTab.js, papersTab.js | identical | benign today, fragile |

Plus two **functionally-identical** core helpers (`normalizeCourseCode`,
`isKnownCourseCode`, same regex/body across reviews/papers/studyGroups/routineState) —
benign today but fragile; allowlisted pending shared-module extraction.

Source-mode unit tests and dev/e2e (un-bundled ESM) **cannot** reproduce these because the
collision only exists in the flattened production bundle.
