# Changelog

All notable changes to Shohoj are recorded here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);

## [Unreleased]

### Fixed
- **The assistant can answer about seats now.** Asking "are there open seats in MAT216?" never actually worked: the seat lookup crashed inside the assistant every time, and the model covered for it with a vague answer instead of a number. The section feed is now read correctly, and cached briefly so a run of seat questions doesn't re-download it each time. (#553)

### Changed
- **The assistant answers faster.** Several things were making you wait that had nothing to do with the answer: the model was reasoning harder than these questions need, the whole section feed was re-downloaded for every seat question, your data was re-uploaded before every question even when nothing had changed, and the reply waited on internal bookkeeping to finish. All four are fixed, with no change to what it can answer or to the rule that it only ever reads your own data. (#553)

### Added
- **The assistant runs on a free model tier.** Shohoj is free and funded by one person, so the assistant now runs on Google's free Gemini tier by default — no billing, no per-question cost, no reason to leave the feature switched off. Paid models stay wired as a fallback for whoever wants to fund one: if the free tier's shared quota runs out, a configured paid provider picks the question up. Same three tools, same rules, same guarantee that it only ever reads your own data. (#550)
- **A spending ceiling on the assistant.** The assistant talks to a paid API on one person's key, so it now has a monthly cap: estimated spend accumulates per calendar month, and once it reaches the configured ceiling the assistant declines further questions until the month rolls over rather than quietly running up a bill. The estimate is deliberately pessimistic, so the cap trips early rather than late, and if the ledger can't be read the assistant stops rather than spending blind. Setting the ceiling to zero is a clean off switch that doesn't require pulling any keys. (#544)
- **The assistant only answers questions about your degree.** Shohoj Assistant is now explicitly bounded to what Shohoj is for — your courses, grades, CGPA, prerequisites, registration, seats, routines and degree progress, and using the app itself. Anything else, including coursework it could technically do for you, gets a one-line decline pointing back at what it can actually help with. (#544)
- **The assistant keeps answering when Claude is having a bad day.** Shohoj Assistant now has a second model behind it: Claude answers as before, and if that request fails for an infrastructure reason — the API is down, we're rate-limited, the request times out — the same question is quietly retried on OpenAI instead of showing you "temporarily unavailable". You don't see a choice or a switch; you just see an answer. It only ever runs when the first attempt has already failed, and a model that answers or declines on the merits is left alone rather than second-guessed by a second model. Both providers use the identical system prompt, the identical three tools, and the identical rule that they can only ever read your own data. Either one can be turned on independently: with neither configured the assistant stays hidden rather than offering a button that can't answer. (#544)
- **Shohoj Assistant on the main site.** The assistant was only reachable from the beta app; it now has a launcher in the bottom-right corner of the main page, so you can just ask — "what GPA do I need for a 3.5?", "can I take CSE370 next semester?", "are there seats in MAT216?" — and get an answer from your own saved data, with the grading rules and prerequisite logic the calculator already uses. It follows you across tabs, and the starter questions change with where you are: seat questions on Seat Status and Routine, CGPA questions on the calculator. Your chat survives switching tabs but never leaves your browser — nothing is stored on any server, and closing the tab clears it. Anything you've just typed is synced before the first question, so it answers on your current grades rather than yesterday's. It reads only your own data, and only when you're signed in: signed out, there's no launcher at all, and neither is there when the assistant's backend isn't available, so it never offers an answer it can't give. (#533)
- **Next registration — what you can actually sign up for.** Your `/profile/` page now works out next semester's options instead of leaving you to cross-reference a transcript against a curriculum PDF. Joining the section feed's prerequisite rules against your imported grade sheet, it shows **Unlocked now** (everything on offer whose prerequisites you've met), **One course away** (courses that open the moment you pass one specific course — and only when that course is itself takeable right now, so it's a real next step rather than a different wall), and your **highest-leverage course**: the single thing you can take that opens the most further courses. The rules are read properly, so `(PHY111 AND MAT110) OR (MAT105 AND PHY110)` needs either pair, not all four, and when you're short it names the easiest route in rather than listing every alternative. Grades count the way BRACU counts them — any passing letter or a P clears a prerequisite; F, F(NT), W and I don't, so a failed course correctly reappears as the thing to retake. Nothing here can tell you you're ineligible by mistake: a rule Shohoj can't read is treated as no prerequisite, the course stays listed, and the page tells you how many it couldn't read so you can check with your advisor. No transcript imported yet gets an invitation to import rather than an empty page. (#478)
- **Per-course marks tracker — what you need on the final.** Every other projection in Shohoj is denominated in "GPA across your remaining credits", which is true and not something you can act on in week 9. Running-semester course rows now carry a **📊** button that opens a marks panel: enter each component off your syllabus (midterm, quizzes, assignment — weight, marks scored, marks available) and Shohoj answers the question students actually ask each other. It shows your marks in hand, the letter you're on pace for, the honest floor and ceiling (the best and worst letter still arithmetically possible), and — for every target still reachable — the mark you need on what's left, e.g. "A- needs 91.7% of the remaining 60%". A target you already hold whatever happens next is reported as secured, meaning secured under a zero on everything remaining, not under your current average; a target that has become impossible disappears instead of showing a number above 100. Half-known syllabuses are the normal case, not an error: if your weights don't total 100% you still get every figure, with a note saying which part of the course they describe. Nothing here touches your CGPA on its own — a button applies the pace letter to the course when you want it counted, and clearing the last component leaves your data exactly as it was before you tracked anything. Available on both the classic calculator and the React Router shell, computed by one pure, unit-tested model. (#500)
- **Withdrawn (W) courses read as withdrawals.** A W now renders as its own badge on the course row instead of an empty grade-point box that looked like half-finished typing, and the retake strategy offers withdrawn courses as candidates — priced honestly, since re-enrolling adds credits rather than replacing a grade, and skipped when you have already retaken the course. (#499)
- **Graduation estimated as a range, not a false point.** The degree tracker's graduation estimate now carries the window around it — earliest and latest — derived from the spread of your own per-semester credit loads (drop the single slowest and single fastest once there are four or more, then use what's left). With a handful of semesters to go on, a statistical confidence interval would be false rigour; a trimmed observed range is something you can check by eye. Semesters where you cleared nothing are excluded from the pace but still count on the timeline, and summary blocks — whose semester count is itself an estimate — don't feed the range at all. (#503)
- **Milestone ladder in the goal simulator.** Before you name a target, the simulator now leads with the standing ladder — Perfect Standing, Higher Distinction, Distinction, Good Standing, Satisfactory, and getting off academic probation — marking each as secured, still reachable, or out of reach against your completed CGPA. (#502)
- **Retake candidates rank by value, not just size.** The Smart Retake & Repeat table can be ordered by **Best value** (CGPA gained per credit re-sat, the new default) or **Biggest jump** (largest absolute CGPA gain), because a 1-credit D and a 3-credit C are different kinds of opportunity and the old single ordering hid one of them. (#501)

Adds traceable `version.json` build metadata, a post-deploy production smoke test, a rollback deploy artifact, path-sensitive + fail-safe Worker and Firestore (rules/indexes only) deploy jobs, dependency-review PR gate (CodeQL already runs via GitHub's default setup), a low-noise grouped Dependabot policy, a Worker `/health` endpoint with request-ids, frontend global error capture, and honest rollback/environments/observability/backup/security-settings docs. No user-facing app behavior changes.

### Fixed
- **"Next registration" is about your degree now.** It used to rank every course in the catalogue, so a CSE student was told their highest-leverage course was BCH101 Basic Biochemistry, above 242 "unlocked" courses and a one-course-away list that opened with seven Architecture courses. It now works from your program's curriculum plus the subjects you've actually taken — so your electives count even when they're outside the standard plan — and, importantly, the "opens N more" ranking is computed within that set, so the number means courses *you* would take. The filter is stated on the card, and **Show all departments** puts the full list back whenever you want it. If your program can't be identified, nothing is filtered rather than guessed. (#539)
- **"Next registration" now actually appears on `/profile/`.** The zone shipped in #478 never ran on the live site: the module that draws it was left out of the profile page's bundle, so it threw at startup and the section stayed blank — while working perfectly in development, which is why it went unnoticed. It renders now, and a new test loads the *built* pages and fails on any startup error, so a feature can't be shipped invisible this way again. (#535)
- **Your semester history on `/profile/` now charts GPA instead of course count.** The bars used to be sized by how many courses each semester held — which for most degrees is 4, 4, 4, 3, 4, five near-identical bars taking the most space in the card and telling you nothing. They now plot each semester's GPA, computed with the calculator's own grade rules from the transcript you already imported (no re-import, nothing uploaded), and a semester with nothing graded says so rather than being drawn as 0.00. The card header used to repeat your CGPA next to the gauge already showing it; it now shows which way your last graded semester moved. The `Name` row, which repeated the name in the page heading, appears only when your transcript's official name actually differs from your account name. (#532)
- **Exam crunch on `/profile/` was showing an exam period that was already over.** It opened on midterms regardless of the date, so weeks after sitting them you were still met with those exams — and with the red "same day · 3.5h later" warning about a turnaround you'd already survived. The block now follows the calendar: it opens on whichever period is still ahead (finals once the last midterm is sat — and if their dates aren't published yet it says so, rather than falling back to last month's), leads with the countdown to your next exam, and measures the crunch over the exams that are left rather than the whole published season. Exams you've already sat keep their place in the order but read as **done** instead of pending. Dates are compared in campus time, so the countdown doesn't shift by a day if you're reading from another timezone. (#530)
- Past-paper/notes preview rendered blank for pre-migration files: objects uploaded before MIME was stored came back as `application/octet-stream`, so the preview iframe couldn't render them. A magic-byte content-type sniff now runs in both the Worker and the client so PDFs and images preview correctly. (#375)
- Lost & Found standalone page rendered in serif — a dropped body font rule. Restored so the page matches the app's typography. (#395)
- `googleClientId` is now treated as the optional secret the CD pipeline documents it as, so builds without it no longer fail. (#392)
- Course autocomplete (shell + island): a grade (or any edit) entered within ~150 ms of picking a course from the dropdown could be silently reverted — the deferred blur commit fired a stale handler that re-committed a pre-edit snapshot of the semester list. The deferred commit now always goes through the current handler. (#320)

## [0.5.0] — 2026-06-19

### Added
- Seat-drop **email alerts** that reach you even with Shohoj closed: when signed in, your Seat Status watchlist syncs to Firestore, and a new cron-triggered Worker handler polls the live feed centrally (one fetch for all users), edge-detects watched sections going full→open, and emails you via Resend. Reuses the Worker's existing service-account wiring; per-user state lives in a client-closed `seatAlertState` collection. Delivery requires a Resend-verified `EMAIL_FROM` sender (SPF + DKIM; see `worker/README.md`) — until that is set the cron still runs but safely skips sends and logs an operational error.
- Routine Builder auto-suggest now prefers **compact days**: a new `gapWeight` factor penalizes idle time between consecutive same-day classes, so packed schedules rank above gappy ones. A "Compact days" toggle (on by default) drives it and re-ranks live, and each suggestion card shows the combination's total gap time (or "compact" when gap-free).
- Seat-drop alerts on the Seat Status tab: watch a full section and Shohoj polls the live CONNECT feed in the background (while open), then fires a browser notification and an in-app toast the moment a seat opens. Watchlist persists across reloads; transition detection lives in the unit-tested `src/core/seatWatch.ts` core.
- Faculty reviews for two new Pharmacy faculty (KMP, MKS) and several CSE hardware faculty (TSE plus extended profiles for AQT, NFS, RAO, TAV), covering PHB201, PHB105, and the CSE251 hardware courses.
- **Routine Builder** tab: assemble a clash-free weekly schedule from the live CONNECT section feed, with overlap-split grid, inline faculty ratings, time-of-day / day-off filters, `.ics` calendar export with class + exam reminders, and QR / link sharing of a routine.
- **Free Rooms** finder: an all-rooms status board (free / in class / in lab + room type) computed from the scheduled timetable, with a per-room full-week availability modal.
- **Profile** account hub (#196): an auth-gated tab that brings a signed-in student's scattered data into one home — account header, seat watchlist with an independent email-alert on/off toggle, saved-routine + semester-plan snapshot, and the student's own reviews. Signed-out users get a sign-in prompt. No BRACU CONNECT credential field exists anywhere; the "your reviews" list uses a privacy-preserving local receipt so no UID-indexed query can de-anonymize a review.

### Changed
- `CONTRIBUTING.md` now documents logical-change commits as the default workflow, with strict one-file-per-commit reserved for explicit requests.
- A `commit-msg` git hook rejects `[skip ci]` and equivalent directives so CI can never be silently bypassed.

### Removed
- Dropped the dead `validReviewPayload` helper from `firestore.rules`.

### Fixed
- Seat-alert (and admin-upload) emails no longer silently fall back to the Resend test sender (`onboarding@resend.dev`), which only delivers to the Resend account owner — so real students received nothing while the cron still logged success. The Worker now treats a missing or test `EMAIL_FROM` as *not configured*, skips sends, and logs a loud operational error instead. **Action required before alerts deliver:** set `EMAIL_FROM` to a Resend-verified sender (see `worker/README.md`).
- A temporary Resend failure no longer advances a user's seat-alert transition state, so a failed full→open email is retried on the next cron tick instead of being lost forever.
- Cron logging is now privacy-safe and richer (`users / watches / transitions / emailed / failed` counts; no UIDs or emails).

### Security
- The client busts out of frames on load to prevent clickjacking.

## [0.2.0] — 2026-05-15

### Security
- Drop `'unsafe-inline'` from `script-src` in the built `shohoj.html` and
  `admin.html`. `build3.py` now computes SHA-256 hashes of every inlined
  `<script>` block and injects them into the CSP meta tag. `style-src`
  still allows `'unsafe-inline'` because templates rely on inline
  `style="…"` attributes; tightening that requires `'unsafe-hashes'` and
  per-attribute hashing, which is queued separately. The built bundle
  has ~340 unique `style="…"` values, most generated at runtime via
  template literals (e.g. `style="background:${_theme().input};…"`), so
  static per-attribute hashing cannot cover them — closing this gap
  requires first refactoring dynamic theming to CSS variables / class
  toggles, tracked separately.

### Added
- Worker test suite at `worker/test/worker.test.js` covering the path
  validators, CORS allow-list behavior, route dispatch (404 / OPTIONS),
  upload validation gates (course code, filename, content length, MIME)
  and the auth-error → 401 branch on every authenticated route.
  Wired into `npm test` and exposed as `npm run test:worker`. Worker
  helpers `isValidCourseCode`, `isValidStoragePath`, `safeFilename`,
  `corsHeaders`, and `AuthError` are now named exports.
